# 二维码离线传输 V1.7

V1.7 同时迭代 Windows 发送器和 Android 接收器，继续兼容 QTX1-W 协议、循环补发、指定补帧、CRC32 与最终 SHA-256 校验。

## Windows 发送器

- 目标帧率范围由 2～20FPS 提高到 2～60FPS，默认 15FPS。
- 移除最高约 25FPS 的 WinForms Timer 路径，改用 Stopwatch 高精度调度与 Windows 1ms 定时器分辨率。
- 30FPS 及以上在二维码绘制后使用 DWM 合成同步，尽量让新二维码赶上下一次屏幕刷新。
- 二维码在后台提前生成，前台仅负责替换已准备好的小型 1bpp 模块位图。
- 使用两个后台生成任务并保持结果顺序；本机对 2800 字节 Version 40-L 帧的多次生成基准约 68.5～79.9 帧/秒。
- 使用容量为 8 的有界缓冲；生成不足时保持当前二维码，不建立无限待显示队列。
- 界面实时显示目标 FPS、实际呈现 FPS 和平均呈现帧间隔。
- 实际呈现速度低于目标 90% 时，状态文字变为橙色，便于判断电脑是否跟得上。
- 保留二维码缩放、全屏、暂停、循环补发和指定补帧。

60FPS 表示每个二维码在 60Hz 屏幕上理论上只完整停留约 16.7ms。电脑达到 60FPS 不代表手机一定能全部识别：手机相机帧率、曝光时间、屏幕刷新相位和二维码密度都会影响有效吞吐。建议先比较 60/45/30/20/15FPS 的手机有效接收速度，而不是只比较桌面端数字。

## Android 接收器

- 默认采用 CameraX `ImageAnalysis.STRATEGY_KEEP_ONLY_LATEST` 与 ZXing-C++ 3.1.1。
- 直接读取 `YUV_420_888` 的 Y Plane，不经过 Canvas、RGBA 和 JavaScript 灰度转换。
- 单分析线程、单 ZXing-C++ Reader，不建立解码等待队列。
- 首次完整帧定位后缓存 ROI；缓存连续失败 2 次立即回到完整帧重新定位。
- 开发者模式可选择固定每 N 帧完整定位，并可对照 ZXing-C++、BarcodeDetector 和本地 jsQR。
- 保留摄像头手动切换、传输计时器、缺帧列表、图片/视频/文字预览和文件保存。

## 成品

```text
发布成品\V1.7\二维码发送器V1.7.exe
发布成品\V1.7\二维码接收器V1.7.apk
```

Windows 构建：

```powershell
.\build-v1.7.ps1
```

Android 构建：

```powershell
.\build-android-v1.7.ps1
```

旧的帧标记试验版位于 `归档-旧帧标记V1.7`，V1.6.3 及更早版本均保留。

# 二维码离线传输 V1.7.1

V1.7.1 只迭代 Windows 发送器；Android V1.7 没有代码变化，不需要重新安装 APK。

## 元数据支持中途加入扫描

- 点击开始发送后出现的第一张元数据二维码固定停留500ms，提高手机刚开启扫描时的识别成功率。
- 每轮开始都会显示一个元数据二维码；第二轮起的轮首元数据保持100ms。
- 此后每发送64个数据帧，再插入一次元数据二维码。
- 第二轮及后续循环继续使用同样的插入规则，手机可从传输中途开始扫描。
- 除首次元数据外，循环元数据固定停留100ms，不受数据帧FPS设置影响。
- 元数据结束后立即进入普通数据帧，按照界面设置的 2～60FPS 发送。
- 元数据停留不计入数据帧实际FPS统计。

手机已建立当前接收任务后，会按会话ID识别后续帧；重复元数据不会清空已接收的数据。尚未开始扫描的手机通常最多等待64个数据帧即可遇到下一张元数据。

## 所有二维码统一外框尺寸

- 元数据、数据帧和轮次结束帧严格使用相同的目标外框边长。
- 手机缓存的ROI不需要适应外框放大或缩小。
- 元数据继续保留低版本二维码的稀疏结构，不强制填充成Version 40。
- 使用最近邻绘制，避免灰色模糊边缘。

## 二维码尺寸提高到150%

- 修复界面初始显示100%、内部实际仍为78%的初始化错误。
- 尺寸输入上限从100%提高到150%。
- 30%～100%在当前二维码区域内缩放。
- 101%～150%会扩大发送窗口和二维码区域，保持二维码及白边完整。
- 窗口扩展受屏幕工作区域限制；F11可获得该屏幕上的最大完整尺寸。

## 高帧率发送

- 数据帧支持2～60FPS。
- 两个后台任务并行生成二维码并按原始顺序显示。
- 使用8帧有界缓冲，不建立无限待显示队列。
- 界面显示数据帧的目标FPS、实际呈现FPS和平均帧间隔。
- 高FPS下等待上一帧完成DWM提交后再呈现下一帧，不向UI堆积任务。

## 成品与构建

```text
发布成品\V1.7.1\二维码发送器V1.7.1.exe
```

构建命令：

```powershell
.\build-v1.7.1.ps1
```

手机端继续使用：

```text
发布成品\V1.7\二维码接收器V1.7.apk
```
